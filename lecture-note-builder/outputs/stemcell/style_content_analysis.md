# 말투 · 문장 구성 · 내용 선택 분석 — 사람 정리본 vs 프로그램 (줄기세포 강의)

- 대상: 사람 작성 MOM(9쪽) / 프로그램 `outputs/stemcell`(12쪽). 본문만 비교(표지·요약·Check·퀴즈 제외).
- 측정: 문단·표 칸을 문장 단위로 나눠 종결 형태·길이·기호를 셌다. 내용 선택은 스크립트 33개 구간(¶)을 기준으로 대조했다.
- 사람 정리본은 이번 생성의 입력이 아니었다(그림만 사용). 이 문서는 **다음 생성을 위한 규칙 후보**를 찾는 분석이다. 규칙은 사용자가 승인한 것만 반영한다.

## 2. 말투

### 2-1. 레지스터를 두 개로 나눈다
| 용도 | 사람 | 프로그램 |
|---|---|---|
| 내용(사실·연구) | 한다체. **연구 서사는 과거형**(“수행했다, 개선되었고, 더 좋았다”), 일반 사실은 현재형(“~이다”) | 한다체 + 정의형·명사 종결이 섞임 |
| 표 칸·목록 | **명사형/명사 종결**(“증식에 한계가 있음”, “윤리적 부담이 적고 안전함”) | 한다체 문장 또는 라벨:내용 |
| 작성자 → 독자 메모 | **합니다체**(“매우 빠르게 넘어갔습니다.”, “(작년에는 강조하고 출제예고도 하셨으나 … 끝내셨습니다.)”) | 한다체(“3분 동안만 발표하고 넘어갔다”) |

→ 사람은 **내용 = 한다체 / 메모 = 합니다체**로 화자를 구분한다. 프로그램은 메모도 한다체라서 내용과 메모가 섞여 읽힌다. (표지 코멘트는 양쪽 모두 합니다체)

### 2-2. 교수의 표현을 남기는 방식
- 사람: 교수의 인상적인 비유만 **짧게 따옴표**로 남긴다 — “앞날이 막막하다”, ‘도토리 키재기’, ‘5G 시대에 2G폰’, ‘뭉치면 살고 흩어지면 죽는다’. 설명 문장에는 교수 발화 투(“~거든요”)가 없다.
- 프로그램: 같은 비유를 남기되 따옴표가 16회로 많고, 연자 발화를 문장 안에 풀어 쓴 곳이 많다.

### 2-3. ‘교수님’ 표기 — 사용자 규칙과 갈리는 지점
- 사람은 **인용형**(“교수님은 ~라고 하셨다”)을 쓰지 않는다 → 사용자 규칙(인용 삭제)과 같다.
- 대신 **소유형**을 7회 쓴다: “교수님의 연구팀에서는 iPSC에 집중”, “초기 교수님 연구에서는 …”, “교수님 방식 = allo”. 강의 대부분이 **교수 본인의 연구**라서 일반 사실과 구분하려는 표시다.
- 프로그램은 이를 “연자/연자팀”으로 22회 썼다 — 학생 정리본에서는 쓰지 않는 말이고 횟수도 많다.
- ❓ **사용자 결정 필요**: ‘인용형 금지’는 유지하되, 연구 소유를 밝히는 “교수님 연구팀”은 허용할지.

## 3. 문장 구성

| # | 사람의 패턴 | 예 (사람) | 프로그램 현재 |
|---|---|---|---|
| S1 | **한 줄에 한 사실**, 짧게 | “ECM은 연골세포의 생존과 기능 유지에 중요한 역할을 한다.” | 한 줄에 2–3개 사실을 `—`, `·`, `→`로 잇는다 |
| S2 | **표 앞 도입문 → 표** | “줄기세포를 분화능에 따라 분류하면 다음과 같다.” → 표 | 표·가로 칸이 소제목 바로 뒤에 나온다 |
| S3 | **세부 뒤 ‘즉’ 정리문** | “즉 조직학적으로 좋은 것은 스페로이드 제형이나 practical하게 사용하기 좋은 것은 single cell이므로 둘 사이의 중용이 필요하다.” | 정리문 없음(0회) |
| S4 | **절 끝 인과 다리** | “이렇게 세포 자체를 치료제로 이용하는 경우 … 근거를 충분히 확보하기 힘들어서 세포에서 유래된 다른 물질을 치료제로 개발하는 시도가 이루어졌다.” | 다리 문장 1개(회색 작성자 괄호로) |
| S5 | **실험 서사 = 방법 → 결과 → 의미, 줄마다 한 절** | “연구에서는 mitochondria를 분리해서 동물모델 무릎에 투여하였더니 / 대조군에 비해 … 개선되었고 / 특히 … 더 효과가 좋았다.” → “즉 … 치료가 될 수 있음을 밝혀냈다.” | 한 줄에 방법·결과·부연을 모두 |
| S6 | **예시 = 이름(영문): 한 줄** | “카티스템(Cartistem): 메디포스트에서 개발한 줄기세포 치료제” | 굵은 이름 + 긴 설명 |
| S7 | **물음으로 여는 결론** | “단순 MSC 치료의 미래는? “앞날이 막막하다”라고 볼 수 있다.” | 없음 |
| S8 | 기호는 최소, 인과에만 `→` | “→ 품목허가가 취소됨” | 기호가 구조를 대신 |

### 같은 내용을 사람 방식으로 다시 쓰면 (예시)
**프로그램(현재)**
> - MIA 골관절염 동물 모델 무릎에 **분리한 미토콘드리아**를 넣었더니 연골이 많이 개선(빨간색 = 연골 기질) — 세포가 에너지를 받아 분화·이동이 빨라지고, 연골 덩어리 제작에도 도움

**사람 방식(S1·S5·S3)**
> 교수님 연구팀은 미토콘드리아를 분리해 골관절염 동물 모델(MIA)의 무릎에 투여했다.
> - 대조군보다 연골 손상이 개선되었고
> - 성체줄기세포보다 iPSC에서 분리한 미토콘드리아의 효과가 더 좋았다.
> 즉, 젊은 미토콘드리아(충전된 건전지)를 넣어 주는 것 자체가 치료가 될 수 있다.

## 4. 어떤 내용을 넣는가

### 4-1. 구간별 처리 (스크립트 ¶ 기준)
| 내용 유형 | 예 (¶) | 사람 | 프로그램 |
|---|---|---|---|
| 정의·분류·비교 | 분화능 위계(9), ESC vs MSC(7–8), auto vs allo(12), single vs spheroid(25) | **반드시 표** | 표/가로 칸 |
| 교수 연구의 방법→결과→의미 | ECM(15), 미토콘드리아(17–18), RCT(19–20), 스페로이드 전임상(28–29) | 3–6줄, 결과 위주 | 세부까지 |
| 제품·사례 | 카티스템, 인보사, Neuronata, Ryoncil, MegaCARTI | **이름 + 한 줄** | 이름 + 경위·수치 |
| 결론·메시지 | 다음은 재생 의학(6), MSC의 앞날(21), 3가지 전략(27), iPSC가 처방 목록에(33) | 유지(박스·따옴표) | 유지 |
| 도입 맥락 | 아카데미아→클리닉→인더스트리(3), 1890년·100/30/15년 간격(3–5) | **뺌**(발전 순서만 1문장) | 연도·간격까지 |
| 일화·개인사 | 야마나카 사진·노벨상(10), 김만수 교수(11), 정준영 교수(20), 국정감사·주주(23), 친구 회사(24), 할머니 등산 이야기(26), 베트남 휴가(31) | **뺌** (야마나카는 통째로) | 일부 유지·회색 생략 표시 |
| 장식 수치 | 2,000억(21), 1회 2,000만 원(21), 31명 중 30명(25), 200 µm(28), 8마리·4마리(28–29) | **뺌** | 유지 |
| 결론을 뒷받침하는 수치 | iPSC auto **10억 원·2년**(30), 12 vs 12·9개월(20), 3명·30명(31–32) | **유지** | 유지 |
| 진행 안내 | 50분(2), “3분 동안”(31) | 메모로 1줄(합니다체) | 회색/꼬리표 |
| 시험 정보 | PAD, 출제예고, 강조 여부 | 파랑 줄 + 코멘트 | 파랑 + 꼬리표 + 표지 집계 |

→ 사람의 선택 기준은 **“결론·비교를 뒷받침하는가”**다. 같은 돈 숫자라도 10억·2년(auto가 안 되는 이유)은 남기고 2,000억·2,000만 원(이야깃거리)은 뺐다.

### 4-2. 사람이 **추가**한 것 (스크립트에 없거나 약한 것)
- 개념 구분 각주(“Spheroid: 3D 세포 집합체 / Organoid: 장기 유사 3D 구조”)
- 절 사이 인과 다리(S4), 정리문(S3)
- 수업 메모(“작년에는 강조하고 출제예고도 하셨으나 슬라이드 30장을 3분 만에 끝내셨습니다”)

### 4-3. 단순화의 대가 (사람 쪽 정확도)
- “T2 mapping에서는 유의한 효과가 있었으니 절반의 성공” — 스크립트는 **경계 수준, medial compartment에서만 p < 0.05**. 사람의 압축이 결과를 조금 과장했다. 프로그램은 이 부분이 더 정확하다.
- “중간 단계 10–20년” — 스크립트는 “대략 20년”.
→ 압축 규칙을 들일 때도 **통계·조건(“~에서만”, “경계 수준”)은 남긴다**는 단서가 필요하다.

### 적용 방법(승인 후)
- C1–C5, C7: 스킬 `readable-note-organizer`·`my-writing-style`에 규칙으로 추가하고, 검증기에 **줄 길이·기호 밀도 경고**(`LINE_TOO_DENSE`: 60자 초과 + `—`/`·` 2개 이상)를 둔다.
- C6: 사용자 결정에 따라 `my-writing-style` 규칙 1의 범위를 고친다.
- C8–C9: `--density review` 모드로 구현(기본은 지금처럼 전부 보존).
- 승인된 규칙은 `style_rules/approved_rules.json`에 근거(이 문서)·예시·적용 강의 유형과 함께 저장한다.
