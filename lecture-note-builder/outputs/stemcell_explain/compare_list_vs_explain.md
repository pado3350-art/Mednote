# 나열식(개조식) vs 설명식(교과서식) — 줄기세포 강의 비교

같은 입력(스크립트 33 ¶, 슬라이드 그림 15장, PAD DOCX)과 같은 규칙(L1–L9, 파랑 = PAD 전용, 한다체)으로 두 번 썼다.

| | 나열식 | 설명식 |
|---|---|---|
| 파일 | `outputs/stemcell/` | `outputs/stemcell_explain/` |
| 템플릿 | `mom_compact.yaml` | `mom_explain.yaml` (compact + `basics_box: true`, `basics_label: 핵심 답`) |
| 작성 코드 | `examples/stemcell_note.py` | `examples/stemcell_explain_note.py` |
| 앞쪽 요약·시험 정리, QUIZ | 같음 | 같음(재사용) |

## 1. 숫자로 본 차이 (앞쪽 요약·QUIZ 제외 본문)

| 지표 | 나열식 | 설명식 |
|---|---|---|
| 쪽수 | 12 | 12 |
| 검증 오류 / 커버리지 | 0 / 100% | 0 / 100% |
| § 수 | 16 | 14 |
| 본문 글자 수 | 7,701 | 9,675 (+26%) |
| 문장 수 / 평균 길이 | 195 / 38.5자 | 231 / 40.9자 |
| 문장 단위 | bullet 98, para 1 | para 56, bullet 2 |
| 접속어(그래서·즉·그런데·반면·때문·결국·다만…) | 20 (100문장당 10.3) | 33 (100문장당 14.3) |
| 질문형 문장·제목 | 3 | 5 + 제목 14개 전부 질문 |
| 그림 상자(figure_side) | 15 | 10 |
| 개념 Check | 13 | 12 |
| UNGROUNDED 경고 | 44 | 14 |

- 문장 길이는 거의 같다. 설명식이 길어진 것이 아니라 **문장 사이를 잇는 말(그래서·즉·그런데)이 늘었다.** 글자 수 +26%는 대부분 이 연결 문장과 "왜?"에 대한 답에서 나왔다.
- 같은 12쪽에 들어갔다. 대신 그림 상자를 15개에서 10개로 줄였다(설명 흐름을 끊지 않도록 핵심 그림만 남김).
- UNGROUNDED가 크게 줄었다. 원문 발화를 문장 단위로 이어 써서 스크립트와 유사도가 오히려 높아졌다.

## 2. 같은 부분 나란히 보기

**MSC 임상(RCT)**

나열식:
> - 대조군 12명과 MSC군 12명을 1년 동안 관찰했다.
> - 통증은 **9개월째에만** WOMAC pain과 VAS pain 점수가 유의했다.
> - MRI상 연골 재생은 유의하지 않았다.
> - T2 mapping으로 본 연골의 질적 변화는 약간 유리했다.
> - 다만 **medial compartment에서만** p < 0.05였고 lateral compartment는 차이가 없었다.

설명식 (제목: *MSC를 환자에게 직접 넣으면 효과가 있었나?* / 핵심 답: *통증은 9개월째에만 줄었고 연골 재생은 증명되지 않았다. 절반의 성공이었다.*):
> 세포 유래 물질이 아니라 세포 자체는 어떨까? … 대조군 12명과 MSC군 12명을 1년 동안 관찰했다. 통증은 **9개월째에만** … 유의했다. 기대했던 MRI상 연골 재생은 유의하지 않았다. T2 mapping으로 본 질적 변화는 약간 유리했지만, **medial compartment에서만** p < 0.05였다. 즉 통증은 일부 줄었지만 연골의 양적 재생 증거는 얻지 못했다.

→ 사실은 똑같다. 설명식은 앞 §(세포 유래 물질)에서 넘어오는 질문 한 줄과 결론 한 줄("즉 …")이 붙는다. 다음 §은 "그렇다면 MSC 치료제의 미래는?"으로 이어져 **각 §이 앞 §의 결론에서 생긴 질문**이 된다.

**세 가지 전략(재료·제형·경로)**

나열식은 ①②③ 소제목 아래 bullet. 그런데 한 문장이 두 bullet로 갈라졌다("기질 없이 배양하면 1주일 안에 죽거나 / fibroblast로 변성된다").
설명식은 "첫째, **재료**다. MSC로는 한계가 뚜렷했다. 그래서 iPSC로 바꾼다." 식으로 **문제 → 그래서 → 해결**이 한 문단 안에 있다. 제형에서는 "single cell은 편하고 spheroid는 기능이 좋다 → 즉 둘의 **중용**(injectable spheroid)"까지 논리가 닫힌다.

## 3. 장단점

| | 나열식 | 설명식 |
|---|---|---|
| 처음 공부할 때(이해) | 사실은 다 있지만 "왜"를 스스로 이어야 한다 | 질문 → 답 → 이유로 읽혀 한 번에 이해된다 |
| 시험 직전(복습·암기) | 훑어보기 빠르고 숫자가 눈에 띈다 | 문단 속 숫자를 찾아야 한다 → **핵심 답 상자 + 굵게**로 보완 |
| 비교·사례·수치 많은 부분 | 강하다(표·columns) | 문단이 길어지고 가독성이 떨어진다 |
| 개념·기전·"왜 이렇게 하나" | 약하다(근거가 bullet 사이에서 끊김) | 강하다 |
| 작성 위험 | bullet 쪼개기로 문장이 깨질 수 있다 | 연결어를 만들다 보면 근거 없는 인과를 덧붙일 위험 → 검증기 UNGROUNDED와 `origin: author`(회색 괄호)로 관리 |

## 4. 권장: 혼합형

같은 강의 안에서도 부분마다 맞는 형식이 다르다.

1. **앞쪽 요약·시험 정리**: 지금처럼 표·도식(둘 다 공통).
2. **개념·기전·전략 §** (왜 재생 의학인가, 줄기세포 위계, ECM·mitochondria가 왜 효과가 있나, 재료·제형·경로 전략): **설명식** — 질문형 제목 + 핵심 답 1줄 + 정의→왜→어떻게→한계→그래서 문단.
3. **사례·수치·비교 §** (MSC RCT 수치, 국내 허가 제품·경쟁사, 동물 실험 결과, 임상 1·2상): **나열식** — bullet·columns·표. 다만 § 끝에 "즉 …" 결론 한 줄을 붙인다.
4. § 사이 다리 문장("그렇다면 …?")은 두 형식 모두에 넣는다. 나열식에서 가장 싸게 흐름을 얻는 방법이다.

## 5. 프로그램에 들어간 것

- `templates/mom_explain.yaml`: 설명식 템플릿(`basics_label: 핵심 답`, 6 min/쪽 대신 5 min/쪽 예산).
- `FormatOptions.basics_label`: 기본정석 박스 이름을 템플릿에서 바꾼다(기본값 "기본정석"은 그대로).
- 테스트 `tests/test_compact.py::test_explain_template_question_answer_box`.
- 스킬 `readable-note-organizer` 0c절: 설명식 작성 규칙과 혼합형 기준.

혼합형을 기본으로 바꾸는 것은 아직 하지 않았다. 두 PDF를 읽어 보고 정하면 규칙(L10)으로 승인 저장한다.
