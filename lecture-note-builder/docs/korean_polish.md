# 한국어 윤문 3종 (grammar-checker · humanizer · style-guide)

`daleseo/korean-skills`(`.agents/skills/`, `.claude/skills/`에 링크)를 **강의록·PAD 해설·스토리라인 본문을 다 쓴 뒤 빌드 전에 반드시** 순서대로 돌린다. 승인 규칙(L1–L34)과 `my-writing-style`이 3종보다 **항상 우선**한다.

## 순서와 역할
1. **grammar-checker** — 맞춤법·띄어쓰기·조사·구두점. 확실한 오류는 바로 고친다.
2. **style-guide** — 문서 안의 일관성(어조, 용어, 숫자·단위, 목록, 따옴표). 문서 타입 = *기술/학술 혼합 → 한 문서 안 다수결*.
3. **humanizer** — AI 티(번역투 `에 대한/을 통해/되어진다`, 군더더기 강조어 `정말/극도로`, `~것입니다` 남발, 3박자 나열, 쉼표 과다). **사실·수치·용어·교수님 강조는 그대로**, 문장만 다듬는다.

## 이 프로젝트의 덮어쓰기 (3종 지침보다 우선)
| 항목 | 이 프로젝트의 규칙 |
|---|---|
| 어조 | 본문 **합니다체**(L5 v2), 표 칸 **개조식**(명사형, ‘-음/-함’), 제목·(1)줄은 명사형. 한다체로 바꾸지 않는다 |
| 교수님 강조 | 문장 끝 ‘~라고 강조하셨습니다’(L6 v2, 빨강). humanizer가 ‘강조’ 표현을 줄이자고 해도 유지 |
| 의학 용어 | `한글(English)` 병기·영어 용어(L25)는 그대로 둔다. ‘외래어 통일’ 제안은 용어집 기준 하나로만 |
| 가운뎃점 | 짝·공통성분(`신체적·정신적`, `서파·렘수면`)만 허용. 독립 항목 나열(`나이·성별·학력`)은 쉼표 |
| 숫자·단위 | 단위는 붙여 쓴다(`10개`, `80세`, `2년`). 범위는 `~`(`0~4점`, `40~50%`), en dash 금지 |
| 기호 | 정의 `=`, 인과 `→`, 핵심 `★`는 바꾸지 않는다(L34). ‘고쳐 쓰라’는 제안 무시 |
| 따옴표 | 강조·용어는 ‘ ’(작은따옴표), 말 그대로 인용도 ‘ ’. 큰따옴표로 바꾸지 않는다 |
| 파랑·색 | 3종은 색을 건드리지 않는다. 파랑 = PAD 전용 |
| 스크립트 말투 | 교수님 구어체를 그대로 옮긴 인용(예: ‘몰라요’, ‘거기서 또 7을 빼면요?’)은 고치지 않는다 |

## 절차 (한 번에)
1. 쓴 글의 텍스트를 뽑는다: 노트 `*_note.py` 또는 빌드 후 `{out}/*_강의록.md`.
2. 3종을 위 순서로 적용하고, **고친 곳 목록**(전 → 후, 이유)을 남긴다. 의미가 바뀔 수 있으면 고치지 않고 사용자에게 묻는다.
3. 원본 `examples/*_note.py`를 고치고 다시 `build` → `validation_report.md` 오류 0, 커버리지 100% 확인.
4. 윤문으로 숫자·용어가 달라지면 `NUMBER_LOST`/`TERM_LOST`가 잡는다. 잡히면 되돌린다.

## 기억할 점
- humanizer 자연도 등급은 B 이상(S1 0~2건)을 목표로 한다. 교수님 인용·필수 용어는 AI 티로 세지 않는다.
- 같은 사실의 반복은 줄이되 요약·표 구조(L16–L21)는 지우지 않는다.
