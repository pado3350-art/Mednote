# Anatomy Visual Explainer — 해부 구조는 그림으로 설명한다

해부 구조는 **위치·방향·연결**이 핵심이라 글만으로는 머리에 그려지지 않는다. 소절이 구조를 다루면 **그림이 설명의 중심**이고 글은 그림을 읽어 주는 역할이다.

## 1. 언제 쓰나 (감지)
- 한 소절에 해부 용어가 **서로 다른 것으로 3개 이상** 나온다: 핵·신경절·신경·경로/다발·겉질/엽/이랑·혈관·막/공/관·뼈/근육/인대·눈 구조 등(영문 nucleus, tract, cortex, nerve, artery, lobe ...).
- 검증이 알려 준다: `ANATOMY_NO_VISUAL`(경고) — 구조를 설명하는 소절에 figure/figure_side/diagram/그림 있는 concept가 없을 때. 용어 추가는 `meta.anatomy_terms`("a|b|c"), 글만으로 충분한 소절은 `meta.anatomy_text_only`("소절 제목|…")로 끈다.

## 2. 그림 고르는 순서 (반드시 이 순서)
1. **강의자료(슬라이드·사용자 제공 그림)의 구조 그림**을 쓴다 — `figures.json`/`slides/`에서 해당 소절 ¶의 슬라이드 이미지를 찾아 `kind="figure"` 또는 `figure_side`(그림 옆에 핵심 줄)로 둔다.
2. 그림이 없거나 해상도·내용이 부족하면 **도식(diagram)** 으로 그린다: 위치 관계 → `tree`/`compare`, 연결 경로 → `flow`/`cycle`, 층 구조 → `pyramid`. 도식은 강의에서 말한 구조·연결만 넣는다(없는 연결을 지어내지 않는다).
3. MOM(사람 정리본)의 그림은 **스타일 참고만**, 생성에는 쓰지 않는다. 강의에 없던 해부 그림을 임의로 끌어오지 않는다(의학적 사실 추가 금지, 필요하면 보라색 확인 표시).

## 3. 그림과 글을 묶는 법
- 그림 **바로 위·아래에** 읽기 줄 한 줄(L22): “그림의 화살표는 A → B → C 순으로 이어집니다”처럼 **그림 속 이름·방향을 문장으로 옮긴다**. 그림에 있는 라벨이 본문에서 빠지지 않게 한다.
- 구조 이름은 한글만 쓰지 않는다: 잘 안 쓰는 한글 용어는 영어 병기(L25 — 사이막핵(septal nuclei)).
- **한 그림 = 한 질문**(한 쪽 한 앵커, L17). 구조 5개 이상이면 그림을 나누지 말고 한 그림에 두고, 글은 그림 번호/위치 순으로 쓴다.
- 비교가 필요하면(좌/우, 정상/병변) 그림 둘을 `figure_side`/`columns`로 나란히 둔다.
- 기능과 병변을 연결할 때(“여기가 다치면 ~”) 그림에서 해당 구조를 가리키고, 같은 줄에 증상을 쓴다.
- 파랑은 PAD 기출에만. 해부 그림 캡션·라벨을 파랑으로 칠하지 않는다.

## 4. 절차 체크리스트
1. `prepare` 산출물(`storyline.md` 그림 인벤토리)에서 해부 소절을 표시한다.
2. 소절마다 그림 소스 확인(슬라이드/제공 그림) → 있으면 배치, 없으면 도식 설계.
3. 그림 속 글(라벨·수치)을 본문 문장으로 옮겼는지 확인(`IMAGE_LOST`, `NUMBER_LOST`).
4. `python -m app.cli build … ` → `validation_report.md`에서 `ANATOMY_NO_VISUAL`이 없는지 확인, 없애지 못하면 이유를 사용자에게 알린다(그림 자료 없음 등).
5. PDF를 쪽 이미지로 열어 **그림이 잘리거나 글자가 작지 않은지** 눈으로 확인한다.

## 5. 하지 말 것
- 구조 설명 소절을 글·표만으로 내보내기.
- 그림만 붙이고 읽는 법(화살표·위치) 설명 생략.
- 강의에 없는 해부 정보를 도식에 추가.
- 장식용 그림(구조와 무관한 이미지)으로 `ANATOMY_NO_VISUAL`만 피하기.
