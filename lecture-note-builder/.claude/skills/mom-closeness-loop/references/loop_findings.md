## MOM에서 배운 문체 (대상 MOM 기준 — 저자마다 다르다)
- **표 칸**: 개조식. 명사형이나 ‘-음/-함’, ‘~할 수 있음’. 마침표 없음. “BBB를 통과하는 약제를 사용”, “정맥염이 잘 생길 수 있음”, “경구 항생제 섭취가 어려움”.
- 설명 문장·`A.`: 한다체. 작성자 코멘트: 합니다체.
- 영어 용어는 괄호 병기 없이 그대로(“Ceftriaxone, Vancomycin”).
- **저자가 다르면 문체가 다르다**: 신경계 MOM 3건(2025-08)은 합니다·요체가 많았고 이 항균제 MOM은 한다체 + 개조식이었다. 대상 MOM의 끝맺음을 먼저 `compare-mom`으로 재고 따른다.

## 함정 (실제로 겪은 것)
1. **검증기가 문장을 망친다**: 녹취의 영어(`스페시멘(Specimen)`)가 노트에 없으면 `TERM_LOST`가 떠서 문장마다 괄호를 끼웠다. → `meta.omitted_terms`.
2. **keep-with-next는 표를 건너지 못한다**(LibreOffice): 질문 상자를 표로 만들면 제목·상자가 쪽 끝에 남고 표만 다음 쪽으로 간다. → 상자를 테두리 문단으로.
3. **쪽 끝 여백 문단이 빈 쪽을 만든다**: 쪽 끝 상자 뒤의 일반 여백 문단이 넘쳐 새 쪽과 겹쳤다. → 정확한 높이의 얇은 문단.
4. **한글 줄바꿈은 글자 단위**: 칸 너비를 1–3자 넘기면 마지막 한두 글자가 혼자 다음 줄로. 영어 구절은 공백에서 바뀌어 문제없다. → 줄을 나누고 `TABLE_ORPHAN`이 한글 끝에서만 경고.
5. **측정이 못 보는 것**: 숫자는 괜찮은데 쪽 이미지에서 빈 쪽, 갈라진 상자, 고아 글자가 나왔다. 두 가지를 모두 한다.
6. **푸시 실패가 숨는다**: `git push | tail -1 && break`. → 종료 코드로 확인.
7. **문서의 숫자를 기억으로 쓰지 않는다**: 세어서(`note.json`) 쓴다.
8. **강조(굵게)는 환경에 달렸다**: 샌드박스 PDF는 한글 굵게가 없다(Word는 정상). PDF로 검토할 때 강조 체계가 약해 보인다.

## 회차 3: 'AI 같은 문장' 걷어내기 (사용자 피드백, 문체 규칙 *후보* — 승인 전이라 approved_rules에는 넣지 않음)
- 내용 없이 앞을 여는 문장(‘아래 세 소절이 이 순서다’, ‘~를 한 번 더 정리한다’, ‘~를 살펴보자’, ‘다시 나온다’)은 뺀다. 교수 발언임을 구분해야 할 때만 출처를 문장에 둔다.
- 표·bullet을 되풀이하는 소절 끝 ‘즉 …’ 정리문과 복습 반복은 뺀다. 강의에서 실제로 답한 질문(‘같은 뇌수막염 의심 환자라도 왜 달라질까?’)은 살린다.
- 표 칸에는 판단 단서만: ‘혈류가 감소하면 약이 충분히 도달하지 못할 수 있다’ → ‘혈류 감소 → 약 도달 저하 가능’.
- 제목 아래 핵심 답이 있으면 본문 첫 문장은 답을 되풀이하지 않고 이유·사례로 시작한다. 단, 원문 내용은 줄이지 않는다.
- 도구: `meta.recap_lines: "off"`(노트 단위 스위치, `abx_meta.json`)이면 `LIST_NO_SUMMARY` 대신 `RECAP_LINE`이 ‘즉 …’ 줄을 잡는다. `ANNOUNCE_SENTENCE`, `ANSWER_REPEATED`는 항상 켜짐. 결과: 13쪽 → 12쪽, 오류 0, 테스트 114개.
